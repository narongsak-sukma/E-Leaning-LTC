## 0. กฎลำดับการรัน — อ่านก่อนรันทุกครั้ง (P8 / re-seed)

> **สำคัญที่สุดของฉบับนี้** — 09A และ 09B **เปลี่ยนรหัสผ่านของบัญชี demo จริง** (citizen และ staff.exam ตามลำดับ) การรันผิดลำดับจะทำให้สคริปต์รอบหลัก/สคริปต์อื่นล็อกอินไม่ได้

1. **เงื่อนไขเริ่ม 09 ทั้งรอบ**: รอบหลัก UAT-01..08 **จบทั้งรอบแล้ว (P8)** — หรือถ้าถูกสั่งให้รันก่อนรอบหลักจบ ต้องไม่กลับเข้าสคริปต์รอบหลักที่ยังไม่ได้รันโดยไม่ re-seed ก่อน
2. **ลำดับที่กำหนด**: `P8 เสร็จ → 09A → re-seed → 09C → 09D → 09B → re-seed (คืนฐานส่งมอบ)`
   - เหตุผล: 09A เปลี่ยนรหัส citizen → re-seed คืนค่า env ก่อนแตะบัญชีอื่น · 09C/09D อ่านอย่างเดียว (กดยกเลิกทั้งหมด ไม่บันทึกอะไร) จึงวางก่อน 09B ได้ปลอดภัย · 09B จบด้วย logout-all + รหัสใหม่ → re-seed ปิดท้ายเพื่อคืนฐานให้รอบถัดไป
3. **คำสั่ง re-seed**: `bash scripts/uat-seed.sh` (idempotent — รันซ้ำ = ตั้งรหัสผ่านทุกบัญชีกลับเป็นค่า `UAT_DEMO_PASSWORD` จาก env ของเครื่องสาธิต) · หลัง re-seed **MFA factor ของบัญชีเจ้าหน้าที่ยังอยู่เดิม** (seed ไม่แตะ auth.mfa_factors — ยืนยันจาก supabase/seed-uat.sql หัวไฟล์) การล็อกอิน staff:exam หลัง re-seed จึงยังเป็นสองขั้นด้วย secret เดิมที่ `mfa/uat.staff.exam.md`
4. **ห้าม**: ห้ามเริ่ม 09A/09B เมื่อมีสคริปต์อื่นค้างอยู่กลางทาง · ห้ามข้ามขั้น re-seed ที่กำหนด · ห้ามแก้ `scripts/uat-seed.sh` (A-6b — การเพิ่มบัญชี seed ใหม่อยู่นอก fence)
5. **ถ้ารหัสเพี้ยนระหว่างรัน** (เช่น 09A ตั้งรหัสใหม่แล้ว crash ก่อนจด): ทางกู้เดียว = re-seed แล้วเริ่มสคริปต์นั้นใหม่ — จดเหตุลง run-log.md

### กติกา verdict/หลักฐาน (สืบทอดจาก UAT-EXECUTION-PLAN §5 — ใช้กับทุกขั้นของ 09)

- **ผ่าน** = หน้าจอตรง "ผลที่คาดหวัง" ครบทุกอนุประโยค และมีหลักฐาน (step-NN.png)
- **ไม่ผ่าน** = สิ่งที่เห็นจริงต่างจากคาดหวัง (จดสิ่งที่เห็นจริงลงหมายเหตุ + ความรุนแรง: **ก** กั้นธุรกิจหลัก / **ข** มีทางเลือกยังใช้ได้ / **ค** ภาพ/ข้อความ)
- **N/A** = ทำไม่ได้จากสภาพแวดล้อม — ไม่นับเป็นความล้มเหลวของแอป
- จับภาพหลักฐาน **ก่อน** กดขั้นถัดไปเสมอ (ภาพต้องเห็นสิ่งที่ขั้นนั้นอ้างถึง)

### 3.1 กลุ่ม UAT-09A — ลืมรหัสผ่าน → รีเซ็ตผ่านอีเมล (F1 · บัญชี `uat.citizen@ltc.local`)

```gherkin
Feature: UAT-09A ลืมรหัสผ่านและตั้งรหัสใหม่ผ่านลิงก์อีเมล
  ผู้ใช้ที่ลืมรหัสผ่านขอตั้งรหัสใหม่เองได้ที่ /forgot-password
  ระบบส่งลิงก์ตั้งรหัสผ่านใหม่ผ่านอีเมล (ตรวจที่ Mailpit ของ stack)
  และแสดงข้อความตอบกลับชุดเดียวกันเสมอไม่ว่าอีเมลจะมีในระบบหรือไม่ (anti-enumeration)

  Background:
    Given รอบหลัก UAT-01..08 จบแล้ว (P8) หรือเพิ่ง re-seed ด้วย bash scripts/uat-seed.sh
    And รหัสผ่านปัจจุบันของ uat.citizen@ltc.local คือค่าจาก UAT_DEMO_PASSWORD ("รหัสเดิม")
    And ไม่มีเบราว์เซอร์ context ใดล็อกอิน uat.citizen ค้างอยู่

  Scenario: A-1 หน้าลืมรหัสผ่านแสดงครบและตรวจรูปแบบอีเมลก่อนส่ง
    When เปิด http://localhost:3001/forgot-password
    Then เห็นหัวเรื่อง "ลืมรหัสผ่าน" พร้อมคำอธิบาย "กรอกอีเมลที่ลงทะเบียนไว้ ระบบจะส่งลิงก์ตั้งรหัสผ่านใหม่ให้" และลิงก์ "กลับไปหน้าเข้าสู่ระบบ"
    And ช่อง "อีเมล" และปุ่ม "ส่งลิงก์ตั้งรหัสผ่านใหม่" แสดงอยู่
    When กรอก "not-an-email" ลงช่องอีเมล แล้วกดปุ่ม "ส่งลิงก์ตั้งรหัสผ่านใหม่"
    Then เห็นข้อความ "รูปแบบอีเมลไม่ถูกต้อง กรุณาตรวจสอบอีกครั้ง" และไม่มีคำขอถูกส่งออกไป

  Scenario: A-2 ขอลิงก์ด้วยอีเมลจริงได้ข้อความยืนยันชุดเดียวกันเสมอ
    When กรอก uat.citizen@ltc.local แล้วกดปุ่ม "ส่งลิงก์ตั้งรหัสผ่านใหม่"
    Then เห็นข้อความ "ถ้าอีเมลนี้มีในระบบ ระบบได้ส่งลิงก์ตั้งรหัสผ่านใหม่ไปที่อีเมลแล้ว" พร้อมบรรทัด "ตรวจสอบโฟลเดอร์ junk/spam ด้วย หากไม่พบในกล่องจดหมายเข้า"
    And ข้อความนี้ไม่เผยว่าอีเมลมีในระบบจริงหรือไม่

  Scenario: A-3 อีเมลที่ไม่มีในระบบได้ข้อความเดียวกันเป๊ะ (anti-enumeration) [ทางเลือก — ถ้าไม่ชน rate limit]
    When กรอกอีเมลที่ไม่มีในระบบ (เช่น uat.zero@ltc.local) แล้วกดปุ่ม "ส่งลิงก์ตั้งรหัสผ่านใหม่"
    Then ได้ข้อความเดียวกับ A-2 ทุกตัวอักษร
    And ที่ Mailpit ไม่มีอีเมลตั้งรหัสผ่านใหม่ฉบับใหม่ถึงอีเมลนั้น
    But ถ้าชน rate limit (ข้อความ "มีการเรียกใช้บ่อยเกินไป กรุณารอสักครู่แล้วลองอีกครั้ง") ให้จด verdict N/A พร้อมเหตุ แล้วไปขั้นถัดไป

  Scenario: A-4 ลิงก์จากอีเมลพามาถึงฟอร์มตั้งรหัสใหม่ และ token ไม่ค้างใน address bar
    When ดึงข้อความล่าสุดถึง uat.citizen@ltc.local จาก Mailpit (GET http://localhost:8025/api/v1/messages) แล้วคัดลิงก์ตั้งรหัสผ่านใหม่ออกจากเนื้อหาอีเมล
    Then ลิงก์นั้นชี้ปลายทางมาที่ /reset-password ของ origin :3001
    When เปิดลิงก์นั้นใน browser context ใหม่ที่ยังไม่ล็อกอิน
    Then มาถึงหน้า "ตั้งรหัสผ่านใหม่" ในสถานะฟอร์ม (เห็นช่อง "รหัสผ่านใหม่" และ "ยืนยันรหัสผ่านใหม่" กับปุ่ม "ตั้งรหัสผ่านใหม่" — ไม่ใช่การ์ดลิงก์เสีย)
    And address bar ไม่เหลือ token ใน URL (ส่วนท้าย URL ถูกลบออกอัตโนมัติ)

  Scenario: A-5 ฟอร์มตั้งรหัสใหม่ตรวจความยาวและความตรงกันของรหัส
    When กรอกรหัสผ่านใหม่สั้นกว่า 12 อักษร แล้วกดปุ่ม "ตั้งรหัสผ่านใหม่"
    Then เห็น "รหัสผ่านต้องมีความยาวอย่างน้อย 12 อักขระ" และไม่บันทึก
    When กรอกรหัสผ่านใหม่ยาวพอสองช่องไม่ตรงกัน แล้วกดปุ่ม "ตั้งรหัสผ่านใหม่"
    Then เห็น "รหัสผ่านทั้งสองช่องไม่ตรงกัน" และไม่บันทึก

  Scenario: A-6 ตั้งรหัสใหม่สำเร็จ — รหัสเก่าถูกปฏิเสธ รหัสใหม่ใช้เข้าสู่ระบบได้
    When กรอกรหัสใหม่ ("รหัสใหม่ 09A" — ยาว ≥12 ไม่ง่ายเกินไป) ทั้งสองช่องให้ตรงกัน แล้วกดปุ่ม "ตั้งรหัสผ่านใหม่"
    Then เห็นข้อความสำเร็จ "ตั้งรหัสผ่านใหม่สำเร็จแล้ว กรุณาเข้าสู่ระบบด้วยรหัสผ่านใหม่" พร้อมปุ่ม "ไปหน้าเข้าสู่ระบบ"
    When กด "ไปหน้าเข้าสู่ระบบ" แล้วลองล็อกอิน uat.citizen ด้วย "รหัสเดิม"
    Then ถูกปฏิเสธ (ข้อความชื่อผู้ใช้/รหัสผ่านไม่ถูกต้องของหน้าเข้าสู่ระบบ)
    When ล็อกอิน uat.citizen ด้วย "รหัสใหม่ 09A"
    Then เข้าสู่ระบบสำเร็จ (ไม่มีขั้น MFA — บัญชีพลเมืองไม่บังคับ) และไปหน้าหลักได้
```

```gherkin
    And "บริบท ก" ยังล็อกอินอยู่ (โหลดหน้าอื่นที่ต้องล็อกอินซ้ำได้โดยไม่ถูกไล่ออก)
    When เปิด "บริบท ข" ใหม่ ลองล็อกอิน uat.staff.exam ด้วย "รหัสเดิม"

    When ที่ "บริบท ก" ส่วน "เซสชัน" กดปุ่ม "ออกจากระบบทุกเครื่อง" (ใต้คำอธิบาย "ใช้เมื่อสงสัยว่ามีผู้อื่นเข้าใช้บัญชีของท่าน — ระบบจะยกเลิกการเข้าสู่ระบบทุกเครื่องรวมถึงเครื่องนี้")
    Then "บริบท ก" ถูกพาไปหน้า /login (full navigation)
    When ที่ "บริบท ก" กดย้อนกลับ/เปิด /my/security
    Then ถูกพาไป /login (เซสชันเครื่องนี้ตายจริง)
```

### 3.3 กลุ่ม UAT-09C — โมดัล "+ เพิ่มกติกา version ใหม่" + exam_review_mode (F4 · `/admin/assessments` · อ่านอย่างเดียว — กดยกเลิก ไม่บันทึกจริง)


### 3.4 กลุ่ม UAT-09D — หน้ารายละเอียดคลังข้อสอบ (F5 · `/admin/question-banks/{id}` · อ่านอย่างเดียว — เปิดโมดัลแก้ไขแล้วปิดโดยไม่แก้)

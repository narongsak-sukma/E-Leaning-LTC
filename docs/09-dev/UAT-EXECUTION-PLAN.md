## 1. การเตรียมสภาพแวดล้อม (ทำครั้งเดียวตอนต้นรอบ — ประมาณ 10–15 นาที)

### 1.1 ยก production-build runtime (:3001)

```bash
make up-prod          # compose profile "prod" · container ltc-prod-app · host :3001 → container :3000 · NODE_ENV=production
                      # (ครั้งแรก build ใน container นาน — start_period 600s ครุมไว้ · ถ้า CTO เพิ่งรัน battery จบ container นี้ขึ้นอยู่แล้ว)
make ps               # รอ ltc-prod-app สถานะ healthy
curl -sf http://localhost:3001/api/health >/dev/null && echo health=200
```

- service ที่แชร์กับ dev stack (compose project เดียวกัน): **db · Kong :8000 · Mailpit :8025** — UAT ใช้ Mailpit ตรวจอีเมลได้ตามปกติ
- ห้ามใช้ dev runtime :3000 ระหว่างรอบนี้ (กันสับสนหลักฐาน) · ห้าม `reset-db`/`down -v` เด็ดขาดระหว่างรอบ

### 1.2 Seed บัญชี demo + ข้อมูล UAT (idempotent — รันกี่ครั้งก็ได้ · รันซ้ำ = ตั้งรหัสใหม่ทุกบัญชีตามค่าที่ส่ง)

```bash
# ใช้รหัสที่บันทึกไว้ใน .env ของเครื่องสาธิต (ตำแหน่งที่ถูกต้องของค่าจริง — ห้ามใส่ค่าจริงลง repo):
UAT_DEMO_PASSWORD="$UAT_DEMO_PASSWORD" bash scripts/uat-seed.sh

# หรือถ้าต้องการตั้งรหัสเฉพาะรอบนี้ (ความยาว ≥12 ตัวอักษร ตาม GOTRUE_PASSWORD_MIN_LENGTH):
UAT_DEMO_PASSWORD='<รหัสรอบนี้ ≥12 ตัว>' bash scripts/uat-seed.sh
```

- รหัสผ่านชุดเดียวกันทุกบัญชี · สคริปต์พิมพ์รหัสท้ายการรันเฉพาะบน terminal จริง — **ห้ามอัดหน้าจอ/tee ช่วงที่รหัสแสดง** · ถ้าใช้ค่าจาก `.env` อยู่แล้วก็ไม่จำเป็นต้องอ่าน output รหัส
- สคริปต์ต้องเห็น `docker compose ps db` = running (เป็น service เดียวกับที่ prod runtime ใช้ — seed ได้ทั้งสอง runtime)
